# 评论区盖楼

大二的设计，用一个 List 存放当前 floor 楼层下的所有回复，to 为当前楼层的 comment 将放在这个 List 中，由此来构造树形结构

@Data
public class Comment {
    int question;
    long floor;
    String from;
    long to;
    String content;

    List<Comment> comments;
    public void setComments(List<Comment> comments){
        if(this.to != 0){
            return;
        }
        this.comments = new ArrayList<>();
        for(Comment c: comments){
            if(c.getTo() == this.floor){
                this.comments.add(c);
            }
        }
    }
}

public List<Comment> getComments(int question){
    List<Comment> comments = commentMapper.getComments(question);
    for(Comment c: comments){
        c.setComments(comments);
    }
    List<Comment> res = new ArrayList<>();
    for(Comment c: comments){
        if(c.getTo() == 0){
            res.add(c);
        }
    }
    return res;
}

其实也还行，就是每一次都要拿所有的评论出来，如果有只拿某一层的评论的需求，就出大问题了

  • 正常的盖楼，一般只会展示根楼层，在用户点击显示更多的时候，才会展开当前楼层的所有回复，参考贴吧的实现

这里 to 只记录了直接父级，如果要构造树形结构，每一次都要读出所有的评论，实现不了“只读根楼层，再读子楼层”

正确的楼层数据库设计：应设置一个 root 冗余字段，记录每个评论对应的根楼层，同时保留直接父级 to 字段用于构造树形结构

@Data
public class Comment {
    int id; // 通原先的 floor
    int from; // 评论者
    int to; // 直接父级
    int root; // 根父级
    String content; // 评论内容
    int question; // 所属题目
}

这样就可以了，在进入题目展示楼层时，先根据 question 和 to = 0 读出根楼层直接展示，当用户展开某一根楼层的评论时，根据 root 查出当前楼层所有评论，在业务侧构造完整的树形结构返回即可

进一步的两个高并发问题

  1. 热门评论排序（Hot Sort）：冷热分离，一定不能在数据库 order by，而是要单独把热门评论拎出来缓存在 Redis ZSet ，用 socre 表示点赞数，直接 TopK 返回即可，非热点评论才从 DB 里拿
  2. 评论点赞高并发处理（Write Back）：异步回写，每次点赞不直接 update 数据库，而只写 Redis，即执行简单的 INCR 操作，当 INCR 了 100 次，再批量写回数据库，频繁写 DB 是大忌

# PPT 转码

不管是这里的文档解析还是最后生成的 PPT 字符串返回，都是统一的 json 结构，这里要区分文档的两种形态，即

  1. 文件系统里的源文件，这一份会保持文件原有格式
  2. 对象存储系统中的 bdjson 文件，这里存储的是统一的 json 格式数据

用户直接上传文件，只会调用第一个服务，将文件存储在文件系统，保持原有数据格式；但如果涉及文件操作，就需要全部在 bdjson 上进行修改，例如转码、生成、美化

基础侧提供统一处理 bdjson 的接口，根据传入文档类型，返回一份新格式的 bdjson 的文档

// 【反向转码服务】各种原始文档 → 统一 BDJSON，解析外部文件，输出标准 BDJSON
func ConvertToBDJSON(fileBytes []byte, sourceType DocType) (bdjson BDJSON, err error) {
    switch sourceType {
    case DocTypeDOCX:
        return docxToBDJSON(fileBytes)
    case DocTypePPT:
        return pptToBDJSON(fileBytes)
    case DocTypePDF:
        return pdfToBDJSON(fileBytes)
    case DocTypeXLSX:
        return xlsxToBDJSON(fileBytes)
    case DocTypeTXT:
        return txtToBDJSON(fileBytes)
    default:
        return nil, fmt.Errorf("unsupported source type: %s", sourceType)
    }
}


// 【正向转码服务】统一 BDJSON → 各种原始文档二进制，生成可直接落盘的文件字节流
func ConvertFromBDJSON(bdjson BDJSON, targetType DocType) (fileBytes []byte, err error) {
    switch targetType {
    case DocTypeDOCX:
        return bdjsonToDocx(bdjson)
    case DocTypePPT:
        return bdjsonToPpt(bdjson)
    case DocTypePDF:
        return bdjsonToPdf(bdjson)
    case DocTypeXLSX:
        return bdjsonToXlsx(bdjson)
    case DocTypeTXT:
        return bdjsonToTxt(bdjson)
    default:
        return nil, fmt.Errorf("unsupported target type: %s", targetType)
    }
}

  • 在房间建立完成后，后端其实不涉及 WebSocket 的接口了，前端会被动的接收后端 WebSocket 长连接的广播，实时同步最新的文档数据

真正的协同编辑是没有锁的，这里使用到了一种叫做 OT 的算法（Operational Transformation），类似于 git 的 diff 增量同步

  1. 用户的操作在进入 DB 之前先打到 OT 服务器
  2. 用户行为被 OT 服务器转化为原子的、结构化的操作信息，并附带版本号或时间
  3. 对于同一篇文档，根据这样的操作记录实现更新，如果变更位置不冲突，就自动合并，如果冲突，就接收版本号更新或时间靠后的操作记录

每次编辑文档，持久化顺序如下，均通过 NMQ 解耦

  1. 异步更新 BOS 内容 BDJson
  2. 异步更新 MySQL 元数据
  3. 异步更新 ES 索引数据
用户操作
  ↓
WebSocket 接收操作 (wkservice_wsapi服务)
  ↓
经过 OT 服务器进行合并、更新，输出原子操作
  ↓
操作转换成 BDJson 增量更新
  ↓
通过 WebSocket 广播更新给全量在线用户
  ↓
调用 /savebdjson 持久化完整内容
  ↓
调用 wkservice_rtcs_canvas 保存到 BOS
  ↓
异步推送 NMQ 信息写 DB 更新 MySQL
  ↓
更新 ES 文档索引

func InitCoordinationRoom(ctx context.Context, req InitCoordinationRoomParams) (bool, error) {
	var form = map[string]string{
		"docId":   req.DocID,
		"uid":     req.UID,
		"docFrom": req.DocFrom,
	}
	values := url.Values{}
	for k, v := range form {
		values.Set(k, v)
	}
	ralReq := &ghttp.RalRequest{
		Method: "GET",
		Path:   WsapiInitRoomPath,
		Query:  values,
	}
	response := &NoticeCoordinationStatusResp{}
	ralResp := &ghttp.RalResponse{
		Data:    response,
		Decoder: codec.JSONDecoder,
	}
	resource.LoggerService().Notice(ctx, "init coordination room ", logit.AutoField("req", req))
	err := ral.RAL(ctx, WsapiServiceName, ralReq, ralResp)
	if err != nil {
		resource.LoggerService().Warning(ctx, "initroom ral fail", logit.Error("err", err))
		return false, err
	}
	if response.Status.Code != 0 {
		resource.LoggerService().Warning(ctx, "initroom ral code is ", logit.AutoField("req", req))
		return false, err
	}
	return response.Data.Success, nil
}

func (g *savebdjson) OnExecute(ctx context.Context, req ghttp.Request) (interface{}, error) {
	savebdjsonServ := canvas.NewBaseService()
	if savebdjsonServ == nil {
		resource.LoggerService().Error(ctx, "savebdjson service is nil")
		return nil, canvas_error.ErrWkInternalError
	}

	err := savebdjsonServ.SaveBDJson(ctx, &util.SaveCanvasBDJsonRequest{
		UID:    g.param.UIDStr,
		DocID:  g.param.DocID,
		Canvas: g.param.BDJson,
		Bucket: canvas.GetBucket(),
	})
	if err != nil {
		resource.LoggerService().Error(ctx, "save bdjson failed", logit.Error("error", err))
		return nil, canvas_error.ErrWkInternalError
	}

	if g.param.IsCreateThumb {
		canvas.SendScreensshot(ctx, uint64(g.sockID), g.param.DocID, g.param.StoreID)
	}

	updateTime := time.Now().Unix()

	// 发送下游命令号3300013
	var command = map[string]interface{}{
		"command_no": "3300013",
		"opType":     "update",
		"edtDocRec": map[string]interface{}{
			"uid":        g.sockID,
			"showDocId":  g.param.DocID, // 传加密后的docID
			"updateTime": updateTime,
		},
		"isSaveEdtDocRec": true, // 下游逻辑兼容，只入edtdoc_rec表
	}

	_, err = nmq.Call(ctx, servicer.DefaultMapper, command)
	if err != nil {
		resource.LoggerService().Warning(ctx, "send nmq failed", logit.Error("err", err), logit.AutoField("command", command))
		return nil, canvas_error.ErrWkInternalError
	}

	nuid := uint64(g.sockID)
	canvasDocPayload := canvasdoc.CanvasDocPayload{
		DocID:      &g.param.DocIDInt,
		Title:      g.param.Title,
		UID:        &nuid,
		Product:    frtocUtil.Uint8PTR(canvasmaterial.ToB),
		UpdateTime: &updateTime,
		IsHidden:   frtocUtil.Uint8PTR(0),
	}
	canvasDocServiceImpl := canvasdoc.CanvasDocServiceImpl{}
	err = canvasDocServiceImpl.UpdateDoc(ctx, &canvasDocPayload)
	if err != nil {
		resource.LoggerService().Error(ctx, "call nmq failed,UpdateDoc ES", logit.Error("error", err), logit.AutoField("canvasDocPayload", canvasDocPayload))
		return nil, canvas_error.ErrWkCallNmqError
	}

	resp := &savebdjsonResponse{
		UpdateTime: updateTime,
	}
	return resp, nil
}

底层的 SaveCanvasBDJson 函数，调用的是一个叫RtcsSaveCanvasBDJsonPath的微服务，真正的写锁在这个底层服务中实现，上层不加锁

// 保存自由画布内容
func SaveCanvasBDJson(ctx context.Context, req *SaveCanvasBDJsonRequest) error {
	if req == nil {
		resource.LoggerService().Error(ctx, "SaveCanvasBDJson req is nil")
		return errors.New("SaveCanvasBDJson req is nil")
	}
	var header = http.Header{}
	header.Add("Content-Type", "application/json")
	header.Add("Cookie", "BDUSS="+req.BDUSS)
	ralReq := &ghttp.RalPostRequest{
		RalRequest: ghttp.RalRequest{
			Method: "POST",
			Path:   RtcsSaveCanvasBDJsonPath,
			Header: header,
		},
		PostData: req,
		Encoder:  codec.JSONEncoder,
	}
	resp := &SaveCanvasBDJsonResponse{}
	ralResp := &ghttp.RalResponse{
		Data:    resp,
		Decoder: codec.JSONDecoder,
	}
	if err := ral.RAL(ctx, RtcsCanvasServiceName, ralReq, ralResp); err != nil {
		resource.LoggerService().Error(ctx, RtcsCanvasServiceName+"call failed", logit.Error("err", err))
		return errors.New(RtcsCanvasServiceName + "call failed")
	}
	if ralResp.Response() != nil && ralResp.Response().Body != nil {
		defer ralResp.Response().Body.Close()
	}
	if resp.Status.Code != 0 {
		resource.LoggerService().Error(ctx, RtcsCanvasServiceName+"call failed", logit.String("errMSg", resp.Status.Msg))
		return errors.New(RtcsCanvasServiceName + "call failed")
	}
	return nil
}

// RunWenchainRisk 调用文链风控接口
// https://iapi.baidu-int.com/apidoc/shared-73ece047-f989-40a5-b96e-d9a4e23d0a5a
func RunWenchainRisk(ctx context.Context, req WcRiskReq) (resp *WcRiskResp, err error) {
    resource.LoggerService().Notice(ctx, "", logit.Int("aicomm_riskcom_RunWenchainRisk", 1)) // 调用信息日志统计
    ralReq := &ghttp.RalPostRequest{
        RalRequest: ghttp.RalRequest{
            Method: "POST",
            Path:   WenchainRiskCheckPath,
            Header: http.Header{
                "content-type": {"application/json"},
            },
        },
        PostData: req,
        Encoder:  codec.JSONEncoder,
    }

    response := &WcRiskResp{}
    ralResp := &ghttp.RalResponse{
        Data:    response,
        Decoder: codec.JSONDecoder,
    }

    if err := ral.RAL(ctx, WenchainRiskCheckRal, ralReq, ralResp); err != nil {
        // error log
        resource.LoggerService().Error(ctx, "risk_RunWenchainRisk", logit.AutoField("error", err))
        return nil, wkerror.New(wkerror.ErrorCodeCallServiceError, "call wenchain risk service error")
    }

    rawResp := ralResp.Response()
    defer rawResp.Body.Close()

    if response.Errno != 0 {
        resource.LoggerService().Error(ctx, "risk_RunWenchainRisk", logit.AutoField("response", response))
        return nil, wkerror.New(wkerror.ErrorCodeCallServiceError, "wenchain risk service return error")
    }

    resource.LoggerService().Debug(ctx, "risk_RunWenchainRisk", logit.AutoField("response", response))
    return response, nil
}

func GetAndAddLock(ctx context.Context, key string) {
  for i := 0; i < MaxRetryNum; i++ {
    riskLock, setErr := basis.GetRedisIns(ctx).SetNX(ctx, key, "true", 1*time.Second).Result()

AOP 日志切面

@Aspect
@Component
public class LogAspect {

    @Resource
    private LogMapper logMapper;

    private final ObjectMapper objectMapper = new ObjectMapper();

    // 切点：所有加了 @LogAnnotation 注解的方法
    @Pointcut("@annotation(LogAnnotation)")
    public void logPointCut() {}

    // 成功执行后记录日志
    @AfterReturning(pointcut = "logPointCut()", returning = "result")
    public void logAfterReturning(JoinPoint joinPoint, Object result) {
        saveLog(joinPoint, result, null);
    }

    // 抛异常时记录日志
    @AfterThrowing(pointcut = "logPointCut()", throwing = "e")
    public void logAfterThrowing(JoinPoint joinPoint, Exception e) {
        saveLog(joinPoint, null, e);
    }

    // 保存日志
    private void saveLog(JoinPoint joinPoint, Object result, Exception e) {
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        Method method = signature.getMethod();
        LogAnnotation logAnnotation = method.getAnnotation(LogAnnotation.class);

        Log log = new Log();
        // 操作类型
        log.setType(logAnnotation.type());
        // 描述
        log.setDescription(logAnnotation.description());
        
        // 操作人信息，直接从 UserContext 获取当前登录用户信息
        Long uid = UserContext.getUserId();
        String username = UserContext.getUsername();

        log.setUid(uid);
        log.setUsername(username);
        // 操作方法
        String className = joinPoint.getTarget().getClass().getName();
        String methodName = method.getName();
        log.setObj(className + "." + methodName);

        // 结果：0=失败 1=成功
        if (e != null) {
            log.setResult(0);
            log.setDescription(log.getDescription() + "，异常：" + e.getMessage());
        } else {
            log.setResult(1);
        }

        log.setDeleted(0);
        log.setGmtCreate(new Date());
        log.setGmtModified(new Date());

        // 插入数据库
        logMapper.insertLog(log);
        
        // 清空 ThreadLocal，防止内存泄漏
        UserContext.clear();
    }
}

# 消息队列解耦判题业务

设计模式

  • 模板工厂模式：抽象判题流程
  • 策略模式：三种策略编译执行代码
  • 观察者模式：判题机作为消费者监听判题事件

例如车票排队等订单处理的设计

用户从页面查询、填写并发起一次判题请求，具体经过了如下步骤

  1. 从 Redis 读出题目详细信息，进入做题页面
  2. 用户填写表单，包含用户信息、题目信息、用户代码等内容，点击提交
  3. 后端收到请求，生成判题记录编号，而后将判题记录编号作为任务投递给 MQ，同时将记录编号返给前端（生产者的工作完成了）
  4. 判题机作为消费者，读取 MQ 消息，根据编号读数据库信息进行编译执行，并将结果与数据库比对，更新 MySQL 判题记录状态，并把记录状态以{judge:status:记录编号, 1/2/3/4/5}的键值对形式写进 Redis
  5. 用户点击提交后，将收到后端返回的判题编号，前端将根据判题编号不断轮询 Redis 查询判题状态，这一状态将持续 20s 左右，而后再从 MySQL 中拿取判题的详细信息
