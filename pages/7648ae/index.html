# Vibe Coding

From Coder to Builder

Vibe Coding 本质就是自然语言驱动 LLM 直接产出可执行代码（Prompt Engineering），软件从 “工程实践” 退化成 “一个想法”，AI 是编程的义肢，并且随着 Agent 的不断发展，人逐渐编程 AI 的义肢，二者的主导关系在慢慢变化，AI 越来越主动

事实上，产品给我们提需求实际上也是一种 VIbe Coding（什么碳基 Agent）

程序员本质上是把现实需求转变为数字世界的语言描述的“翻译者”，在 AI 的加持下，“翻译”工作变得越来越简单，程序员的意义更多在于“信达雅”的翻译，相信 AI 的不断发展，这样的信达雅的优势也会逐渐减少，以及现实需求本身的完善，而不是仅仅做好“翻译”这件事

# Spec Coding

规约编程（Spec Coding），或者说规范驱动编程（Spec-Driven Development），强调在动手编写代码之前，开发者与 AI 需先共同制定一套关于软件架构、功能边界与业务逻辑的详细规约文档，AI 将严格基于此文档逐点执行开发任务，旨在将 AI 编程从“玄学”拉回“工程学”

原则 解决什么问题
编码前思考 错误假设、隐藏困惑、缺少权衡
简洁优先 过度复杂、臃肿抽象
精准修改 无关编辑、触碰不应碰的代码
目标驱动执行 通过测试优先、可验证的成功标准

Rules：约束智能体的需求文档，统一放在项目根目录的 .rules 文件夹中，说白了就是规范 LLM 行为的文档形式的 System Prompt，在以下四个方面对 LLM 进行提示与约束

  • What：代码库干嘛的
  • Where：目录结构如何组织
  • How：场景流程，few shot
  • Should/Not：应该/禁止做什么

可以参考 Cursor 内置的 Rules，本质上都是一段 markdown 格式的 User Prompt，通过令 AI 先阅读指定文件再进行操作，进行相对规范的操作

  • 单测 rule：unit-test-rules
  • 代码风格 rule：code-style
  • Go 单测 skill：go-unit-test

# Pairing Coding

结对编程最早是 ACM 里的概念，一人编码，一人审查，在结对编程中，编码和审查的角色是随时互换的 —— Comate 厂内的 Copilot

人机协同十二原则

  1. 用注释加强 AI 代码理解：先写注释再编码
  2. 代码人易懂 ＝ AI 易懂，提升代码可读性：保持代码风格；有意义的命名；代码块粒度合适（150 行左右）；先搭架子再填空
  3. 留心 AI 能力范围：AI 后台运行，需要定时检查
  4. 准备私域知识：如优质的 few shot、RAG 等
  5. 编码前多提问：了解 AI 意图，明确个人需求
  6. 编码后 AI 审查：让 AI 审查 AI 代码
  7. 写代码前先澄清：清晰代码意图和功能
  8. 让 AI 复用和扩展个人能力：插件、MCP、Skills
  9. 专注于核心业务，杂活全部交给 AI：如复杂的正则表达式
  10. 不会的、不熟悉的让 AI 帮忙
  11. 人是驾驶者，AI 是辅助手
  12. 接受 AI 的不完美

常见场景

  • 基于注释生成代码（Comment Driven Coding）
  • 根据代码生成注释
  • 充当搜索引擎
  • 单测文件生成

使用经验：在拿到一份项目时

第一步：开启全局上下文并做全盘扫描在你的 AI 对话框里，确保你已经唤起了读取整个代码库的指令，然后发送这个破冰指令

你现在是一个资深的后端架构师，我已经将整个代码库作为上下文发给了你，请你先不要修改任何代码，只做仔细的阅读和审查。请用中文为我总结这个项目的核心信息

1. 这个项目使用的核心技术栈是什么？(包括框架、上下游依赖、状态管理、构建工具等)
2. 请梳理并解释目前的目录结构 (如下各个子目录的作用)
3. 项目的入口文件和核心路由体系是如何组织的，项目暴露了哪些接口

第三步：生成“记忆面包”（沉淀文档）

当 AI 完美回答了前两步后，它此时的脑子里包含了这个项目最完整的信息，但只要开启新对话就会遗忘，所以需要让它把这些信息通过文档的方式固化下来

基于你刚才的审查结果，请帮我生成一份详尽的 PROJECT.md 文档，这份文档的目的是：以后当我开启新的 AI 会话时，只要让 AI 读取这个文档，就能立刻了解项目的全局规范和架构，请排版清晰，包含技术栈概览、 目录说明、核心开发规范等关键信息

# Harness 工程

Rules 通过规则 Prompt 约束 Agent 行为，属于 SDD，Harness 通过严谨的环境条件限制 Agent 行为，属于 BDD

  • SDD（Specification Driven Development）是一种以规范为核心、先写规范再生成代码的开发方法，强调AI辅助下的高效、可控和可追踪的软件开发流程
  • BDD（Behavior-Driven Development）是一种以业务需求为导向的软件开发方法，通过自然语言描述系统行为，促进开发、测试和业务团队的协作

# 可复用技能

MCP：模块化的、标准化的、微服务化的工具调用（function call），让 LLM 快速获取某项技能，包括但不限于搜索网页、生成文档、读写文件

Skill：本质上是渐进式披露的 Markdown 系统提示词，虽然现在还没有明晰的概念提出，但是 Skill 已经明显区分为两类

  • 一种是环内的 skill：给 agent loop 的 skill
  • 一种是环外的 skill：与人交互的 skill

Skill 与 MCP 区别：MCP 需要 JSON-RPC 协议接入并且一次暴露整个 MCP 能力，而 Skills 直接让 LLM 读取 Markdown 文档获取，通过“渐进式披露”提供能力，并且 Markdown 文档较于 MCP 调用更具普适性

一个 Skill 的基本结构

skill-name
├── SKILL.md # 定义、描述 skill
├── scripts/ # 具体的可执行代码脚本，其说明在 SKILL 中定义
├── templates/ 文档模板
├── resources/ 资源文件

# ACE 工程

节省上下文小妙招

  1. 图检索代替 grep：用 CodeGraph 代替全文 Grep 检索，减少 Agent 阅读代码时的 Token 消耗，和 LSP 代替 Grep 的思路类似
  2. 脚本复用：让 Agent 沉淀可执行的脚本，如”构建单测脚本“，让”任务执行“本身成为一种可复用的能力
  3. Agent 的动态工具选择：枚举配置工具名，根据 skill 注入 mcp 工具，用 31B 的小模型决定加载哪些 skill，JEV 和 Decision API 就是这个道理

ACE 上下文工程：解决上下文腐烂

  • 上下文工程 ≠ 精炼总结，压缩 ≠ 总结
  • 压缩可逆，总结不可逆，总结的信息丢失程度远大于压缩，就像 Hash 和 Zip
  • kv cache 和 prompt cache？前缀缓存

# Loop 工程

AI 开发的越快，人工 Review 的积压也越多，效率并没有提升，究其原因，人的注意力是有限的

# A2A Loop

Agent Loop：类似于 Audit Agent 的循环审计设计，旨在“完成任务之前持续工作”，在新的概念里引入了 Loop 过程中的“自学习”能力，正如 Robin 所说，演化能力是 Agent Loop 的精髓

Agent 通信：通过通信共享内存还是共享内存通信？

  • 上下文即 Agent 的内存，很明显，前者更优雅，更符合 go 编码者的习惯，在实践中也更节省
  • 共享上下文 = ReRead，但子 Agent 是隔离的，可以用便宜模型，这样也可以实现节省
  • 在工程实践中，更多可以根据隔离性和任务复杂度适当的选择桥接 or 总机模式

这可以引申到另一个争论，即 Agent as a Tool 还是 Multi Agent，这是架构选择上的考量，优缺点和 Agent 通信大差不差，需要具体问题具体分析

# 递归式自我改进

RSI 重点在于“数据闭环”

AI Coding 的演化一定是：SDD（rules） → BDD（harness） → DDD（loop）（TDD 是手段）

数据闭环是自编译的艺术，两个实例

  • AnyDev 开发与进化闭环：通过 Agent + Workspace + Skills 承接真实需求，需求分析 → 评审（人工介入） → 拉分支开发 → 联调 → PR（人工介入）；在每个需求结束后，进入独立的 s4 阶段，总结、沉淀并补充 Skill
  • “工单” Agent 落地：工单场景的数据闭环，agent 创建工单 → 人工标注有误的工单 → 优化 rag 知识库 → 继续创建工单

Loop 和 RSI

  • codex 的 goal 模式是经典的 loop 实践，让 agent 在 loop 中持续发现、解决问题，实现工作的闭环
  • RSI（Recursie Self-Improvement）递归式自我改进是当前 Loop Engineering 的核心

长时序智能体（long-horizon agents）的优化，通过减少决策轮次来提供任务成功率和上下文长度：[2609.02042] Act More, Decide Less: Skill-Guided Adaptive Action Chunking for Long-Horizon LLM Agents (opens new window)
