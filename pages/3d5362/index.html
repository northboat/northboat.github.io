# Work

# Tencent AnyDev

找工作大多靠狗运，忌讳有总是能找到工作的错觉

  • 修复了一些问题 / bug
  • 整理 / 输出 xxx 的技术方案
  • 开始 / 介入开发
  • 发到了测试环境 / 跟进测试
  • 多谢 / 早
  • 保留下现场？我看看 / 晚点我看看
  • 同步下结论 / 这边情况跟 xxx 同步一下
  • 我感觉是不是 ... 会不会好一点
  • 好我和 xxx 再确认一下 / 和 xxx 确认过了
  • 技术上比较难支持，如果产品坚持，可以讨论一下
  • 完成了这个事项；没事了，忽略吧
  • 快速过一下；简单对一下

汇报严忌记流水账浪费 ld 时间 → 沿故事脉络讲清问题关键，避免讲的太单薄，要有层次感（总分总） → 避免讲太大，开发要落到技术上，突出思考与取舍，用技术痛点突显价值

工程师 = 解决问题的人（总是业务驱动）

  • bingo：经验聪明实干 → 学习能力 → 元认知 loop 迭代，找热钱
  • 幽默小胖：目标驱动，找最短实现路径；开工前对目标，过程中报风险，交付后讲结果，撇清决策责任

Merge 不是起点是起点，做过的需求，要复习巩固，这都是经验沉淀，如果抱着交付就丢掉的心态很难成长

# Baidu Wenku

做业务不会增长技术，只会累积经验，真正的技术成长都是在做业务之余偷学核心代码

熟悉业务，一定要勤问，问清之后再开始编码

  1. 先问架构，摸清组织架构、项目架构
  2. 再问业务，针对具体业务，针对性的逮人问业务流程，上下游调用
  3. 最后问 AI，理清具体代码逻辑，数据流转、状态转移

关于需求，有疑问一定要及时反馈，只要事情和对方有关系就要及时说，切忌单方面做共同决定，永远不要默认他人的决定，即使出现歧义的概率很小也要 mock 到

  1. 问清楚产品需要的效果
  2. 理清楚接口的调用流程，链路一定要 cover 全
  3. 记清楚失败情况的日志

业务上下游调用复杂，沟通强度大，一定要及时发问、对齐、总结、提升

  1. 开发中要注重代码的执行效率和健壮性
  2. 对文库的不同业务逻辑进行梳理并落实到文档上，便于分享和以后回顾，尤其是完善各种接口文档和业务流程
  3. 对于需求中的各种要点要反复推敲，不明白的要及时去核实，遇到的修改点要举一反三，穷举链路，看是否会影响到别的服务，有全局意识
  4. 合作开发中要及时沟通，明确需求后制定设计方案，并给出对应的排期，要有计划去同步，尽可能的查补漏洞，并提前自己的工期

# Huawei ICSL

实习最重要的是拓宽视野，增加知识的广度以确认未来方向，次要是技术积累

  • 打球和做业务一样，都是上网学，固定好框架，发力集中，讲究技巧和效率
  • 最大的优点就是业务理解的好，拆解的好，有自己的思考，擅于把业务做好就是最大的成功

AI 开发是风口

  • 实习：腾讯，字节，阿里，百度，美团，京东
  • 校招：字节，腾讯，OV，虾皮，华为

找工作无非平台、技术方向、Base 地和薪资

技巧和项目

  • 学习方法：记忆曲线、费曼学习法
  • 后端项目（微服务 + DDD）：点赞系统、短链系统、刚果商城
  • 安全项目：RASP 链路监控与漏洞防护
  • 轮子项目：mini spring cloud、guide-rpc-framework

# Life

租房可以提前一天中午到，将行李放在某一个房东处，看半天房，如果没有合适的住一晚酒店第二天再看

  • 应该尽量短租，比如预计三个月，那么就应该先租两个月，把风险控制的小一点
  • 一定要先测完再签合同再交钱
  • 重点检查项：采光，洗衣机排水，花洒出水，空调是否漏水，卫生环境（潮湿、蚊虫等），白天看采光，晚上看隔音

注意通勤时间，不仅仅是时长，还有时间段的限制，先问清楚大概什么时候上下班，再在合适的区间内选取合适的通勤区间

# Balance

不要让 8 小时的工作占据 24 小时的情绪，ld 的情绪要忽略但过脑，厘清诉求，快速制定计划，重点是消除不确定性让 ld 心安

  • 简单煮碗面：先煎西红柿，再煮面，再放蛋，最后放紫菜

能够好好工作的关键在于人脑上下文切换，当同时面临多个需求和多种压力，能够任意的切换对话去应对，是保持工作生活平衡的关键

周末延长五步法

  1. 下班回家先洗澡：切换成生活状态
  2. 周四当大扫除日：为周末提前解决麻烦事
  3. 周五当狂欢日：安排值得期待的事
  4. 周六当早起日：上午可以做很多事
  5. 周日当收心日：早睡觉
